Home Assistant 出于各种用途使用了许多不同的 Docker 容器。不仅 Home Assistant Core 以 Docker 容器的形式提供，我们的 Supervisor 以及所有加载项（add-on）也都基于 Docker。

在许多情况下，我们需要在容器中运行多个进程，而它们都需要被管理。我们过去使用简单的 Bash 脚本来实现这一点，但很快意识到我们需要一个合适的进程管理器来处理这项工作。

我们决定使用 [S6 Overlay init 系统][s6-overlay]，它基于出色的 [S6][s6] 工具集，提供进程监控与管理、日志记录以及系统初始化功能。

S6 Overlay 已被添加到我们的 [Docker 基础镜像][base-imags] 中，Home Assistant 发布的每个 Docker 镜像都使用它。

所有容器均已更新，相关变更由 Home Assistant Supervisor 自动处理；对于 Home Assistant 用户而言，不会有明显影响。

对于在 Docker 上使用 Home Assistant Core 容器的用户，这可能会影响你运行或启动容器的方式。如果你在运行 Home Assistant Core 容器时覆盖（override）了 Docker 的入口点（entry point）或命令，则需要对这些进行相应调整。例如，一些容器管理系统（如 Portainer 和 Synology）会自动为你覆盖这些设置，因此你会受到影响。

在这些情况下：

- 入口点已更改为：`/init`
- 命令（CMD）已更改为：` ` _（空/未设置）_

如果你覆盖命令端点来启动 Home Assistant，入口点中的 init 系统仍会在后台保持运行，并再次启动一个 Home Assistant。这可能导致意外行为。
