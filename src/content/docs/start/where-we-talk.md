Home Assistant 有几个人们聚集的地方。每个地方各有所长。选对地方能让你更快得到答案，也能让对话留在别人日后可以找到的地方。

## 简要版本

| 你想要 | 去哪里 |
| --- | --- |
| 快速提问，或结识其他贡献者 | [Discord](https://www.home-assistant.io/join-chat/) |
| 为你自己的配置寻求帮助 | [社区论坛](https://community.home-assistant.io/) |
| 报告缺陷（bug） | GitHub 上相应仓库的 issue 跟踪器。参见[报告缺陷](/start/report-a-bug/) |
| 建议新功能 | GitHub 上的[功能请求](https://github.com/home-assistant/feature-requests/discussions) |
| 讨论 Home Assistant 的构建方式 | GitHub 上的[架构讨论](https://github.com/home-assistant/architecture/discussions) |
| 询问某个具体的更改 | 对应的 issue 或 pull request 本身 |
| 参加社区同步会议 | [活动日历](/community/reference/events/) |

## 按领域划分

## Discord

[Home Assistant Discord](https://www.home-assistant.io/join-chat/) 是贡献者实时聊天的地方。这是询问“我该从哪里开始？”或“这是个好主意吗？”的最快方式，也是认识项目背后的人的好机会。

在你选择角色之前，贡献者频道是隐藏的。在侧边栏中，选择 **Channels & Roles**，然后选择适合你工作内容的角色。例如：

- **I want to contribute dev skills to Home Assistant** 会给你开发者角色。它会打开 **#developers** 频道和其他开发相关频道。
- 设计师在 **#designers** 相聚。[这个链接](https://www.home-assistant.io/join-chat-design)可以直接带你到那里。
- 测试测试版的人在 **#beta** 相聚。

贡献者频道：

| 频道 | 用途 |
| --- | --- |
| **#developers** | 一般开发 |
| **#core** | 核心与集成 |
| **#frontend** | 前端 |
| **#operating-system** | Home Assistant OS 和 Supervisor |
| **#apple-apps** | Apple 应用 |
| **#designers** | 设计 |
| **#product-and-ux** | 产品与 UX 讨论 |
| **#user-researchers** | 用户研究 |
| **#documentation** | 文档 |
| **#language-leaders** | 语言负责人 |

服务器上有几个地方面向所有贡献者：

- [Building in the open](discord:building-in-the-open) 是面向贡献者的公告频道。关注它以了解项目中的动态。
- [General coding support](discord:coding-support) 是你在代码上遇到困难时提问的地方。
- [project forum](discord:project-forum) 用于持续时间较长的项目，以及团队正在冲刺的较大主题。

本站上的频道链接会打开频道本身。它们只有在你[加入服务器](https://www.home-assistant.io/join-chat/)之后才能使用。

一些领域还有自己的帖子，比如伴侣应用。[上表](#by-area)列出了它们。

一些有帮助的习惯：

- 直接提出你的问题，并提供足够的上下文以便回答。“有人能帮忙吗？”比直接说出问题得到的回答要少。
- Discord 是聊天，聊天记录会滚走。任何对决策重要的内容都应该放在 GitHub 上，以便日后可以找到。
- 不要直接私聊别人请求审查。参见 [pull request 与审查](/start/pull-requests/)。

## 社区论坛

[社区论坛](https://community.home-assistant.io/)是用户互相帮助的地方：配置、自动化和设备。它也是不写代码就能做贡献的好地方。回答问题是你能做的最有价值的事情之一。参见[社区](/community/)。

本页介绍的是贡献者协作的地方。想了解 Home Assistant 社区聚集的所有地方，比如 Reddit、Facebook、线下聚会和地区社区？参见[社区聚集地](/community/reference/channels/)，或 home-assistant.io 上的[社区页面](https://www.home-assistant.io/community/)。

## GitHub

所有代码、文档和决策都存放在 [GitHub](https://github.com/home-assistant) 上。不同类型的对话会去那里不同的地方。

### Issue

Issue 用于缺陷（bug）：即没有按预期工作的问题。每个仓库都有自己的 issue 跟踪器，所以请在代码所在的地方报告问题。[报告缺陷](/start/report-a-bug/)帮助你选择仓库，并解释表单会问什么以及报告之后会发生什么。

Issue 不用于支持问题或功能想法。Issue 表单会指引你到正确的位置：支持问题请前往[帮助页面](https://www.home-assistant.io/help/)，想法请前往功能请求。

### 功能请求

新想法请提交到 GitHub discussions 中的[功能请求](https://github.com/home-assistant/feature-requests/discussions)。先搜索，并对已有的请求投票，而不是开一个重复的请求。选择最合适的分类，比如 **Dashboards & cards** 或 **iOS & macOS**。解释你想解决的问题，而不仅仅是解决方案。其他用户会投票和讨论，产品团队会利用热门请求来制定[路线图](/roadmap/how-it-works/)。

### 架构讨论

关于 Home Assistant 构建方式的问题，比如一种新的实体（entity）类型或适用于所有集成的规则，请在[架构仓库](https://github.com/home-assistant/architecture/discussions)中发起。[架构决策是如何做出的](/architecture/decisions/)解释了一个讨论如何变成决策。

### Pull request

一旦你开始着手某个更改，关于它的对话就会在 pull request 中进行。关于该更改的问题、审查意见和决策都保存在那里。

## 语言

GitHub 上的 issue、pull request 和讨论都使用英语，以便每个人都能跟上。Home Assistant Core 甚至有一个机器人会标记用其他语言撰写的 issue。英语不必完美。如果英语不是你的第一语言，使用工具辅助语法或翻译是可以的：[AI 政策](/start/ai-policy/#non-native-english-speakers)对此有说明。

## 保持友善

[行为准则](/start/code-of-conduct/)适用于上述所有地方。如果你看到不当行为，请使用平台的举报或标记功能，或发送电子邮件至该页面上的地址。
