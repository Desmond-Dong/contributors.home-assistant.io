Home Assistant 运行在数百万个家庭中，用户既有刚刚插上第一个智能插座的新手，也有运行着数百个自动化的资深用户。设计就是让一个产品适用于所有人的方法。这不仅仅是视觉层面：一个设置如何命名、一个对话框询问什么、出错时会发生什么，这些都是设计决策。

本区域是 Home Assistant 的开放设计资源，也是界面外观和行为的参考：包括用法、规格和无障碍（accessibility）。它与 [Brand](/brand/) 区域一起取代了 design.home-assistant.io。它面向所有塑造界面的人：提出更好流程的设计师、构建界面的开发者、斟酌措辞的文案作者，以及任何想了解界面为何如此运作的人。每一页都是同时为设计师和开发者而写的。

你不需要是专业设计师也能提供帮助。如果你能注意到让人困惑的地方，并且能勾画或描述出更好的方式，你就有很多可以贡献的。

## 从这里开始

- [你的第一次设计贡献](/design/first-contribution/)：找到可以着手的内容，分享你的第一个提案。
- [我们如何设计](/design/how-we-design/)：设计在哪里进行、如何撰写提案、由谁决定，以及研究如何影响设计。
- [原则](/design/principles/)：每个设计决策背后的价值观。
- [我们为谁设计](/design/users/)：我们时刻铭记的三类用户。

## 指南与参考

- [基础](/design/foundations/)：颜色、排版、间距、动效和无障碍。一切背后的设计令牌（design tokens）和规则。
- [组件](/design/components/)：界面的构建模块，包含指南、规格、无障碍和代码。
- [模式](/design/patterns/)：组件如何在常见场景中协同工作，例如表单、加载、空状态、错误和确认。
- [仪表盘](/design/dashboards/)：人们放在仪表盘上的卡片，以及如何选择合适的卡片。
- [更多信息](/design/more-info/)：选择实体（entity）时打开的对话框，以及每种类型的实体在其中获得的视图。
- [界面文本](/design/ui-text/)：界面如何说话。
- [Brand](/brand/)：Home Assistant 的个性、语气、名称和标志。它有自己独立的区域，因为它属于每一位贡献者。

## 面向开发者

组件、卡片和更多信息页面将设计放在前面，代码放在最后。跳转到页面末尾的 **In code** 部分，查看元素、其属性以及使用方法。这些页面上的示例是真实的前端组件，可实时运行。

如何搭建前端、构建面板或自定义卡片，以及如何让你的 pull request 获得评审，请参阅 [Frontend](/frontend/) 区域。

## 联系谁

- [Home Assistant Discord](https://www.home-assistant.io/join-chat-design) 上的 **#designers** 频道是设计师聚集的地方。产品和 UX 讨论在 **#product-and-ux** 中进行。看不到这些频道？请在 **Channels & Roles** 下选择相应的角色。
- 提案、反馈和研究在 Open Home Foundation 的 [UX design discussions](https://github.com/OpenHomeFoundation/ux-design/discussions) 中分享。[项目看板](https://github.com/orgs/OpenHomeFoundation/projects/7) 列出了正在进行和计划中的设计任务。
- 界面中的具体问题应作为前端仓库中的 issue 提交，并添加 [`UX`](https://github.com/home-assistant/frontend/labels/UX) 标签。
- 本区域中有页面有误或缺失？请在[本站](https://github.com/home-assistant/contributors.home-assistant.io)上提交 issue 或 pull request。
