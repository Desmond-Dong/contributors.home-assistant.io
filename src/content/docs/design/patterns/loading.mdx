你的家并不总是即时响应的。设备需要一点时间才能应答，历史记录需要获取，备份需要几分钟。良好的等待体验能告诉人们某件事正在发生，以及结果将出现在哪里。

## 何时使用

每当人们可能会面对一个看起来卡住或空白的屏幕时，就应显示加载状态。根据等待发生的位置选择指示方式：

- **整个区域在加载，而你不知道需要多久**：使用[加载指示器（spinner）](/design/components/spinner/)。
- **一个按钮启动了就地运行的操作**：按钮显示它正在忙碌。
- **操作就地完成，结果没有其他地方可以显示**：使用[进度按钮（progress button）](/design/components/progress-button/)。
- **内容加载到你已经了解的布局中**，比如表格的行或磁贴的文字：使用骨架屏（skeleton），即内容形状的灰色占位符。
- **一个操作包含多个步骤**：显示各步骤的进度，让人们知道进行到了哪一步。

## 工作原理

### 加载指示器（Spinner）

加载指示器有四种尺寸：`tiny`（16 像素）、`small`（28）、`medium`（48，默认值）和 `large`（68）。

  <ha-spinner size="small"></ha-spinner>
  <ha-spinner size="medium"></ha-spinner>
  <ha-spinner size="large"></ha-spinner>
</Demo>

### 忙碌按钮

带有 `loading` 的[按钮（button）](/design/components/button/)会用加载指示器替代其标签，并且无法再次点击，从而避免操作被重复启动。前端的确认对话框在操作运行期间会对其主按钮这样做。

进度按钮则更进一步。当操作完成时，它会在绿色按钮上显示对勾图标，或在红色按钮上显示警告图标，持续两秒钟。它只说明*发生了*失败，而不说明*原因*。当人们需要知道原因时，还应显示[错误（error）](/design/patterns/errors/)。

<Demo>
  <ha-button loading>Save</ha-button>
  <ha-progress-button progress>Restart</ha-progress-button>
</Demo>

### 骨架屏（Skeleton）

骨架屏在内容加载期间保持布局不变，这样内容到达时不会发生跳动。前端提供了 `ha-skeleton`，以及用于常见形状的 `ha-skeleton-text` 和 `ha-skeleton-icon`。数据表格、磁贴和设备仪表盘都使用了它们。

### 加载的终点

加载状态总是以下列三种结果之一结束：内容、[空状态（empty state）](/design/patterns/empty-states/)，或[错误（error）](/design/patterns/errors/)。当请求失败时，绝不要让加载指示器一直转下去；当数据仍在途中时，也绝不要显示“这里什么都没有”。

仪表盘卡片遵循同样的规则。每张卡片都会处理加载、错误、不可用的实体（entity），以及不存在的实体。

## 无障碍

- 加载指示器具有进度条的角色，并带有翻译后的“Loading”标签。
- 骨架屏和加载指示器在没有动画时仍保持其含义。当人们要求减少动画时，骨架屏会停止脉动。参见[动效（Motion）](/design/foundations/motion/)。
- 当加载以错误结束时，应以人们可读的文字显示，而不仅仅是一个红色按钮。

## 代码实现

```ts
html`
  <ha-spinner size="small"></ha-spinner>
  <ha-button .loading=${this._saving}>Save</ha-button>
  <ha-progress-button .progress=${this._running}>
    Restart
  </ha-progress-button>
`;
```

当进度按钮的操作完成时，在其上调用 `actionSuccess()` 或 `actionError()`。骨架屏组件 `ha-skeleton`、`ha-skeleton-text` 和 `ha-skeleton-icon` 位于 `src/components/skeleton/` 中。
